# Нагрузочный тест (ТЗ §11, §13)

Дата: 2026-10-23. Машина разработчика (Mac, 11 ядер), PostgreSQL 18 и Redis на той же машине, API — собранная версия (`node dist/main.js`, `NODE_ENV=production`, `connection_limit=30`). На сервере с выделенной БД цифры будут не хуже.

**Данные:** 100 поставщиков, 6 250 товаров, 50 000 вариантов (`pnpm --filter @aesculap/api load:seed` в отдельную базу `aesculap_load`).

## Целевая нагрузка: 200 покупателей

200 соединений, общий темп 70 запросов/с (покупатель кликает раз в ~3 с), кэш каталога холодный на старте.

| Сценарий | p50 | p90 | p97.5 | Ошибок |
| --- | --- | --- | --- | --- |
| Каталог: 20 страниц × 3 сортировки | 55 мс | 132 мс | 235 мс | 0 |
| Фильтры: 120 комбинаций (категория, размер, цвет, цена, сортировка) | 46 мс | 102 мс | 144 мс | 0 |
| Поиск: 30 запросов, включая опечатки и другую раскладку | 89 мс | 203 мс | 235 мс | 0 |
| Подсказки поиска | 52 мс | 109 мс | 237 мс | 0 |
| Карточка товара (200 разных) | 23 мс | 119 мс | 154 мс | 0 |
| Главная | 30 мс | 64 мс | 80 мс | 0 |
| Проверка корзины (10 позиций) | 22 мс | 60 мс | 125 мс | 0 |

Критерий ТЗ — p95 ≤ 300 мс; в таблице более строгий p97.5. Выполнен во всех сценариях.

## Сборка капсулы

20 анкет с разными ростом, размерами, полом, цветотипом и всеми пятью бюджетами (`pnpm --filter @aesculap/api capsule:bench`): **20 из 20** в бюджете и в размере, сборка 0,75–0,95 с при норме 2 с. Для бюджета «до 5 000 ₽» пять вещей не помещаются даже по минимальным ценам — подбор убирает аксессуар и обувь и пишет об этом в объяснении.

## Что изменено по итогам

- Список каталога: минимальная цена (с учётом акции) считается в базе и только для сортировки по цене; было — выборка всех вариантов кандидатов на каждый запрос (4,6 с на первую страницу).
- Фильтры (счётчики), порядок выдачи и состав главной кэшируются в Redis на 30–120 с; одновременные промахи по одному ключу ждут один расчёт. Карточки (цена, наличие, видимость) всегда свежие; снятие с витрины, модерация и выплаты сбрасывают кэш сразу.
- Поиск по опечаткам — оператор `<%` вместо функции `word_similarity`, результат кэшируется на минуту.
- Пул соединений к БД: `?connection_limit=30` в `DATABASE_URL` (по умолчанию Prisma берёт 2 × ядра + 1).

## Как повторить

```bash
psql -d postgres -c "CREATE DATABASE aesculap_load OWNER aesculap"
export DATABASE_URL=postgresql://aesculap:aesculap@localhost:5432/aesculap_load
pnpm --filter @aesculap/api exec prisma migrate deploy && pnpm --filter @aesculap/api prisma:seed
pnpm --filter @aesculap/api load:seed
# API на 4200 с этой базой (NODE_ENV=production требует ALLOW_TEST_PROVIDERS=1 без боевых ключей), затем:
LOAD_CONNECTIONS=200 LOAD_RATE=70 LOAD_SECONDS=20 pnpm --filter @aesculap/api load:test
pnpm --filter @aesculap/api capsule:bench
```
